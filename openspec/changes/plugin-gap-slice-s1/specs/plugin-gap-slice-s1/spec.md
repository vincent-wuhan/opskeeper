## ADDED Requirements

### Requirement: 节点上呼通道必须能服务 BaseTool 形态的工具

节点 agent 的上呼通道 MUST 能服务管理端以 BaseTool 形态实现的工具，MUST NOT 只认闭包注册表。工具的类 MUST 从执行器自身重新推导（MUST 以 `Info().Class` 为准），MUST NOT 采信 manifest 的声明或按工具名推断。

#### Scenario: BaseTool 形态的工具经上呼可用

- **WHEN** 节点 agent 通过上呼通道请求一个由 BaseTool 实现、且该工具在管理端的注册表 bag 中存在的只读工具
- **THEN** 该调用被服务并返回该工具的结果
- **AND** 结果不是 "no such tool"

#### Scenario: 同名工具以 BaseTool 为准

- **WHEN** 一个工具名同时存在于 BaseTool 与闭包注册表，且两者参数形状不同
- **THEN** 上呼调用落到 BaseTool 实现
- **AND** 理由是节点侧 schema 由 BaseTool 的元数据生成，落到闭包会让节点发来的参数按另一种形状解析

#### Scenario: 类从执行器重新推导

- **WHEN** 一个工具的 manifest 声明与执行器 `Info().Class` 不一致
- **THEN** 上呼通道以执行器的类为准

### Requirement: 上呼通道只承载只读工具

上呼通道 MUST 只服务 `Info().Class == "read"` 的工具。非只读工具 MUST 被拒绝，MUST NOT 被降级为"不存在"。保留名单上的只读工具 MUST 同样被拒绝，MUST NOT 出现在可服务名单里。

#### Scenario: 写类工具被拒绝而不是被隐藏

- **WHEN** 节点 agent 请求一个写类或破坏性类工具
- **THEN** 调用被拒绝
- **AND** 拒绝原因指明该工具的类别
- **AND** 该原因 MUST NOT 是 "no such tool"

#### Scenario: 保留名单上的只读工具不被服务

- **WHEN** 一个只读类工具在保留名单上（例如一个 shell、一个 schema 发现工具、一个绑在管理端会话上的对话功能）
- **THEN** 它不出现在上呼可服务名单里
- **AND** 被问到时给出的是"不服务"的理由，而不是"不存在"

#### Scenario: 保留名单逐项有理由

- **WHEN** 审阅保留名单
- **THEN** 每个名字都有写明为什么不能挂在这条通道上的理由

### Requirement: 桥不得复用挂了节点本地技能面的 bag

桥 MUST 从注册表自身构造的 bag 取工具，MUST NOT 复用已被追加节点本地技能工具的 bag。桥 MUST NOT 重复施加不可信输出围栏——围栏由 bag 构造时施加一次。

#### Scenario: 节点本地技能不被抬成上呼可服务

- **WHEN** 一个只由节点本地技能面提供的工具名（主机探针一类）
- **THEN** 它不出现在上呼可服务名单里
- **AND** 节点仍然可以本地服务它

#### Scenario: 围栏只施加一次

- **WHEN** 一个工具的输出是平台外写入的内容
- **THEN** 该输出在桥上仍是围栏后的结果
- **AND** 围栏没有被叠加第二层

### Requirement: 装配时点必须晚于注册表的后置依赖注入

桥 MUST 在注册表的所有后置依赖注入之后构造，MUST NOT 在其之前构造——早于该时点构造会静默丢掉依赖这些依赖的工具。

#### Scenario: 依赖后置注入的工具在桥里

- **WHEN** 一个工具的实现依赖后置注入的依赖（拓扑图、审计流水、代码库一类）
- **THEN** 该工具出现在上呼可服务名单里
- **AND** 桥不是空的

### Requirement: 审计行记录实际服务了调用的面

审计行的 `surface` MUST 由分派结果给出，MUST NOT 由工具名推断。取值 MUST 至少区分：闭包注册表面、中间件适配器面、BaseTool 桥面。

#### Scenario: 桥服务的调用记录为桥面

- **WHEN** 一个由 BaseTool 桥服务的调用被记录
- **THEN** 审计行的 `surface` 是桥面
- **AND** 该取值与"按名字推断"的结果不同时，记录的是实际服务者

#### Scenario: 中间件面与闭包面的取值不变

- **WHEN** 一个中间件适配器工具或一个闭包注册表工具被调用
- **THEN** 审计行的 `surface` 分别是适配器面与闭包面

### Requirement: 包声明与可服务面之间必须有一条可执行的对账

MUST 有一条可执行的对账，断言形式为：**每个包的 manifest 工具名 ∈（上呼可服务名 ∪ 节点本地技能名）**。两侧名单 MUST 来自真实构造（上呼侧由注册表装配得到，节点本地侧由技能注册表枚举得到），MUST NOT 使用手抄的字面量名单。

#### Scenario: 已声明的工具有人服务

- **WHEN** 一个包的 manifest 声明了一个工具
- **THEN** 该工具名出现在上呼可服务名单里，或者出现在节点本地技能名单里

#### Scenario: 缺口的形态能被闸门抓到

- **WHEN** 上呼通道里没有 BaseTool 桥（能力存在但没有接线）
- **THEN** 对账失败，并报出那些既无人上呼服务、也无节点本地技能的工具名
- **AND** 该失败 MUST 是真红：闸门 MUST NOT 在这种状态下通过

#### Scenario: 名单不是手抄的

- **WHEN** 审阅对账的两侧名单
- **THEN** 两侧都能指出各自的构造来源
- **AND** 源码里不存在与构造结果等价的字面量名单

#### Scenario: 不做反向断言

- **WHEN** 审阅对账的断言方向
- **THEN** 只有"声明 ⊆ 可服务"这一个方向
- **AND** 不存在"可服务 ⊆ 声明"的断言

### Requirement: 保持只读策略的前提

上呼通道 MUST 保持只读：装饰器链 MUST NOT 安装审批闸门，MUST NOT 与本通道的账本重复写入执行日志。装饰器的超时、限流与指标 MUST 与既有调用点同形。

#### Scenario: 链上没有审批闸门

- **WHEN** 桥上的一个工具被调用
- **THEN** 调用链上没有需要人工批准的环节

#### Scenario: 执行日志只写一次

- **WHEN** 一个经桥服务的调用被记录
- **THEN** 通道账本里有且只有一行该次调用
- **AND** 装饰器链没有另外写一行执行日志

#### Scenario: 超时与既有调用点一致

- **WHEN** 比较桥上的装饰器依赖与既有调用点的装饰器依赖
- **THEN** 超时上限与限流形态相同
