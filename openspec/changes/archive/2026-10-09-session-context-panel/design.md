## Context

聊天输入已写入结构化 mention token(`ChatInput.tsx:229`,`:163` recomputeMentionContext),Agent 消息内联 `tool_calls[]` 记录了工具调用与结果。因此本会话的运维上下文(@提及对象、知识引用、结晶命中)全部可从**已渲染的消息流**反推,无需任何新增数据接口。这是「零后端改动」设计的前提,也是本 change 的关键约束。

## Goals / Non-Goals

**Goals:**
- 会话侧上下文面板:本会话 @提及的运维对象、引用的知识库文档、命中的自愈结晶规则三类分节呈现
- 可解释性产品化:每条上下文可溯源(来自哪条消息),点击运维对象跳详情
- 推导逻辑与 UI 解耦:纯函数 `deriveSessionContext(messages)` 可单测

**Non-Goals:**
- 零新增数据接口,全部从已渲染消息流反推
- 上下文只读,不可在此编辑或删除
- 不做手动挂载上下文(留 D6 或单独立项)
- 不改消息流渲染(ChatThread/MessageBubble/ChatInput 不动)
- 不逐个工具名硬编码白名单,按工具类别映射(知识类/结晶类)

## Decisions

- **D1 数据源=消息流反推**:`deriveSessionContext(messages)` 纯函数扫描消息数组——mention token 解析出 `mentions[]`(按 type+id 去重),`tool_calls[]` 按工具类别映射分别产出 `knowledgeRefs[]` 与 `crystallizations[]`。无新增请求、无缓存层。
- **D2 工具类别映射而非白名单**:维护「工具类别 → 特征」映射(知识检索类/结晶类),新工具落在同类时自动纳入;不逐个工具名硬编码。
- **D3 面板形态**:宽屏对话页右列;窄屏可折叠侧板;默认折叠,展开态记忆(经 zustand persist)。面板打开不改变消息流宽度计算以外的任何布局。
- **D4 溯源**:每条上下文条目携带来源消息标识,展开可定位到消息;点击运维对象跳对应详情页(既有路由)。

## Risks / Trade-offs

- [消息流反推只覆盖「已渲染」的上下文,Agent 内部未落在消息里的依据不可见] → 明确边界:面板呈现的是「对话中出现的依据」;更深的依据可视化属后续方向,不在本 change 承诺
- [工具结果体积大,面板摘要可能截断] → 条目只列名称/命中数/跳转,不在面板内展开完整结果
- [token 格式演进导致解析失配] → mention 解析集中在一个函数,格式变更多测一条路径即可

## Migration Plan

纯前端增量;回滚即移除面板入口与推导模块,消息流不受影响。无数据迁移。
