## Context

后端已具备简报所需的全部地基:report 生成链路(防幻觉契约——数字必须有来源,否则留空)、report-schedule 调度(`ReportKind='daily'`,`cron_spec` 可配)、IM bridge 推送通道(feishu/dingtalk/telegram/slack)。11 个内置 persona 体系支持新增「值班简报员」。D1(deliverable-surface-deepening)交付物卡落地后,简报作为 report 交付物可直接在对话流内预览。

设计原则:**只汇总与建议,不执行任何变更**;数字无来源就留空——这是简报可信度的底线,与报表防幻觉契约一脉相承。

## Goals / Non-Goals

**Goals:**
- 每日值班简报自动生成并推送:五小节模板(昨夜事件摘要/待审批项含双签进度/告警趋势/结晶自愈次数/今日值班与关注)
- 调度复用 report-schedule,默认每日早晨、时间可配
- 简报是 report 交付物,复用 D1 交付物卡呈现,可归档回看
- 推送经既有 IM 渠道,摘要 + 回链

**Non-Goals:**
- 不新建推送通道
- 不做复杂订阅个性化 UI(默认一次/天,时间可配)
- 简报只汇总与建议,不执行任何变更
- 不在夜间推送

## Decisions

- **D1 简报=report 交付物**:走既有 report 生成链路(含防幻觉契约),`ReportKind='daily'` 复用;不新建独立简报模型。生成物天然获得列表回看与交付物卡呈现。
- **D2 persona 驱动生成**:新增预设 persona「值班简报员」,系统提示词限定「汇总与建议,不执行变更」;生成由调度触发而非用户会话。
- **D3 调度参数**:默认每日早晨 **09:00** 触发(Q4 已定,2026-10-08 用户选定),`cron_spec` 可配;默认推送渠道 **飞书**(Q4 已定),渠道未配置时降级为仅生成不推送;不在夜间推送作为模板硬约束。
- **D4 推送内容=摘要+回链**:IM 推送五小节的一句话摘要与 `/reports/<id>` 回链,正文留在平台内(经 D1 卡片预览),不把全文灌进 IM。
- **D5 平静态**:当日无事件与待审批时,五小节对应位置显示「平静」态而非空白或编造内容。

## Risks / Trade-offs

- [统计口径(昨夜边界、告警趋势窗口)不明确导致数字可疑] → 五小节每节定义明确统计窗口;无来源留空(既有防幻觉契约)
- [IM 渠道未配置时推送无落点] → 渠道未配置时仅生成简报不推送,简报仍可在平台内回看
- [生成失败静默缺报] → 调度失败可见(复用报表任务失败态),不伪造「平静」报

## Migration Plan

增量:新增 persona + 简报模板 + 默认调度配置。回滚 = 停用调度;已生成简报是普通 report 交付物,无需清理。无数据迁移。
